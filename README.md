# ODT, Markdown, TXT and PDF Converter

Консольная утилита на Python для конвертации ODT в EPUB, Markdown, PDF и TXT, Markdown и TXT — в EPUB или PDF, а PDF — в EPUB.

## 🚀 Возможности

- ✅ **Сохранение форматирования**: заголовки, абзацы, жирный текст, курсив, подчёркивание, зачёркивание, цвет текста
- ✅ **Таблицы**: полная поддержка таблиц с объединением ячеек
- ✅ **Списки**: маркированные и нумерованные списки
- ✅ **Изображения**: встроенные изображения из ODT автоматически переносятся в EPUB
- ✅ **Обложка**: поддержка JPEG/PNG/GIF/WebP/SVG/BMP/TIFF обложки с автоматическим поиском
- ✅ **Ссылки**: гиперссылки сохраняются
- ✅ **Стили**: CSS-стили генерируются из ODT-стилей
- ✅ **Метаданные**: автор, издатель, название и язык задаются через CLI или по умолчанию; дата генерации добавляется автоматически
- ✅ **Авторские права**: значение `dc:rights` задаётся параметром `--rights` или по умолчанию
- ✅ **Кириллица**: полная поддержка кириллических названий файлов и содержимого
- ✅ **Другие форматы**: конвертация в Markdown, PDF и TXT через Pandoc
- ✅ **Текстовые источники**: исходные `.md`- и `.txt`-файлы можно конвертировать в EPUB или PDF через Pandoc
- ✅ **PDF → EPUB**: текст извлекается через `pdftotext`; если текстового слоя нет, страницы добавляются в EPUB как изображения через `pdftoppm` (Poppler) и Pandoc
- ✅ **Папка изображений → EPUB**: изображения включаются в книгу в естественном порядке имён файлов
- ✅ **Оформление и оглавление**: можно загрузить пользовательский CSS и добавить видимое интерактивное оглавление
- ✅ **Аудио и видео в EPUB**: файлы из `--media-dir` добавляются в книгу как встроенные медиафайлы с отдельной страницей воспроизведения
- ✅ **ODT → EPUB без зависимостей**: использует только стандартные библиотеки Python 3.6+

## 📦 Требования

- **Python 3.6+**
- **Стандартные библиотеки Python**:
  - `zipfile` - работа с ZIP-архивами
  - `xml.etree.ElementTree` - парсинг XML
  - `argparse` - обработка аргументов командной строки
  - `os`, `sys`, `pathlib` - работа с файловой системой
  - `uuid` - генерация уникальных идентификаторов
  - `datetime` - работа с датами

Для конвертации ODT в EPUB внешние зависимости не нужны. Для ODT в Markdown/PDF/TXT, Markdown/TXT в EPUB/PDF и папки изображений в EPUB установите [Pandoc](https://pandoc.org/installing.html). Для PDF в EPUB нужен Poppler (`pdftotext`, а для сканов без текста — `pdftoppm`). Для создания PDF также требуется настроенный PDF-движок, например LaTeX. При запуске программа проверяет наличие Pandoc и утилит Poppler в `PATH` и предупреждает об отсутствующих; в режиме `quiet` предупреждения скрыты.

## ⚡ Быстрый старт

### Обработка текущей директории

```bash
python convert.py
```

Конвертирует поддерживаемые документы в EPUB в текущей директории и поддиректориях. Если документов нет, а есть изображения, они будут собраны в один EPUB.

### Конвертация одного файла

```bash
python convert.py document.odt
```

Результат: `document_(14:30_25.12.2024).epub` в той же папке.

Конвертация в Markdown, PDF или TXT выполняется через Pandoc:

```bash
python convert.py document.odt --format md
python convert.py document.odt --format pdf
python convert.py document.odt --format txt
```

Результат будет сохранён в той же папке с соответствующим расширением (`document.md`, `document.pdf` или `document.txt`). Для другого пути используйте `-o`, например `-o output.pdf`.

### Конвертация Markdown, TXT и PDF в EPUB

```bash
python convert.py "Моя книга.md" --format epub
python convert.py "Моя книга.txt" --format epub
python convert.py "Моя книга.pdf" --format epub
```

Для Markdown и TXT также доступна конвертация в PDF:

```bash
python convert.py "Моя книга.md" --format pdf
python convert.py "Моя книга.txt" --format pdf
```

Файлы `.md`, `.txt` и `.pdf` можно указывать напрямую или передать папку — при выборе EPUB скрипт найдёт в ней ODT, Markdown, TXT и PDF-файлы; при выборе PDF — ODT, Markdown и TXT. TXT и извлечённый из PDF текст передаются Pandoc как Markdown. Если в PDF нет текстового слоя, страницы преобразуются в PNG и включаются в EPUB как изображения; для этого OCR не нужен. Для PDF → EPUB нужны Poppler и Pandoc; для вывода в PDF также требуется PDF-движок.
Результат сохраняется рядом с исходным файлом с расширением `.epub` или `.pdf`; путь можно задать через `-o`.

### Создание EPUB из папки с изображениями

```bash
python convert.py "Страницы книги" --format epub
```

Если в папке нет поддерживаемых документов, все изображения из неё добавляются в один EPUB в естественном порядке (`страница2` перед `страница10`). По умолчанию учитываются вложенные папки; `--no-recursive` ограничивает поиск указанной папкой. Поддерживаются JPEG, PNG, GIF, SVG, WebP, BMP и TIFF. По умолчанию результат сохраняется рядом как `Страницы книги.epub`; путь можно задать через `-o`. Для создания EPUB нужен Pandoc. Если в папке есть документы для конвертации, изображения не создают отдельную книгу.

### С обложкой

Если обложка находится рядом с ODT и имеет то же имя:

```bash
# document.odt + document.jpg → document.epub
python convert.py document.odt
```

Обложка будет найдена автоматически!

Или явно указать обложку:

```bash
python convert.py document.odt -c cover.jpg
```

### Папка для поиска обложек

Если `-m` / `--media-dir` не указан, скрипт ищет обложку в текущей папке (`.`) и её подпапках. Папку поиска можно задать явно:

```bash
python convert.py document.odt --media-dir /path/to/media
# Короткая форма:
python convert.py document.odt -m /path/to/media
```

Флаг `--no-recursive` отключает поиск в подпапках.

При создании EPUB из любого поддерживаемого источника скрипт также ищет в этой папке медиафайлы и добавляет найденные в EPUB. Поддерживаются аудио `.mp3`, `.m4a`, `.m4b`, `.aac`, `.ogg`, `.oga`, `.opus`, `.wav` и видео `.mp4`, `.m4v`, `.ogv`, `.webm`. В книге создаётся отдельная страница с HTML5-плеерами, на которую ведут элементы навигации EPUB. Используйте `--media-dir` для выбора папки; поиск учитывает `--no-recursive` и правила исключений.

Воспроизведение зависит от EPUB-читалки и поддерживаемых ею контейнеров и кодеков; часть читалок может показать страницу, но не воспроизвести отдельные файлы.

### Несколько файлов и директорий

```bash
python convert.py file1.odt file2.odt /path/to/books
```

### Полные параметры

```bash
python convert.py document.odt -c cover.jpg -o output.epub -t "Моя книга" -a "Иван Иванов" -l ru
```

## 📖 Использование

### Синтаксис

```bash
# Обработка текущей директории
python convert.py [options]

# Конвертация одного или нескольких файлов
python convert.py <file1.odt> [file2.odt ...] [options]

# Обработка директории
python convert.py <directory> [options]

# Комбинированный режим
python convert.py <file.odt> <directory> [options]
```

### Позиционные параметры

- `paths` - пути к файлам или директориям (если не указаны, обрабатывается текущая директория)
  - Если путь указывает на файл — конвертируется только этот файл
  - Если путь указывает на директорию — конвертируются поддерживаемые входные файлы в ней
  - Можно указывать несколько путей одновременно

### Опциональные параметры

- `-c, --cover <path>` - путь к обложке (JPEG/PNG/GIF/WebP/SVG/BMP/TIFF)
- `-o, --output <path>` - точный путь к выходному файлу для одного источника или папка назначения для одного/нескольких источников. Относительный путь считается от папки исходного файла (для папки изображений — от неё самой), в том числе при пакетной обработке всех типов источников. Папку можно указать существующую либо новую без расширения (например, `converted/`); для EPUB из ODT по умолчанию добавляется суффикс с датой.
- Перед пакетной обработкой проверяются совпадения выходных путей между результатами и с исходными файлами. При конфликте обработка прекращается до создания результатов; перезапись самого источника запрещена даже с `--force`.
- `--no-timestamp` - не добавлять суффикс даты/времени к имени EPUB, созданного из ODT. Работает для одиночной и пакетной обработки; у других маршрутов суффикс не добавляется и без этого флага.
- `--log-file <path>` - записывать подробный журнал в файл в режиме добавления; относительный путь считается от текущей папки. В файл записываются подробности даже при `--mode quiet`.
- `--format {epub,md,pdf,txt}` - формат результата; `epub` по умолчанию. ODT можно конвертировать во все указанные форматы; Markdown и TXT — в EPUB/PDF через Pandoc; PDF — в EPUB через `pdftotext` и Pandoc. Если формат источника совпадает с форматом результата, файл пропускается без изменений. Для создания PDF дополнительно нужен PDF-движок.
- `--input-formats <list>` - ограничить поиск в папках заданными форматами через запятую: `odt`, `md`/`markdown`, `txt`, `pdf`, `images` (папки изображений — только для EPUB). Параметр можно повторять. Явно переданные файлы этим фильтром не ограничиваются.
- `--mode {quiet,summary,verbose}` - режим вывода; по умолчанию `verbose`
- `--ask-overwrite` - спрашивать перед заменой существующего выходного файла
- `--force` - принудительно перезаписывать выходные файлы без подтверждения
- `-t, --title <string>` - название книги
- `--identifier <string>` - идентификатор книги в метаданных EPUB (например, ISBN или URN); если не задан, сохраняется или генерируется автоматически
- `-a, --author <string>` - автор книги; по умолчанию используется автор из источника, если он задан, иначе `Шмель`
- `--publisher <string>` - издатель книги; для ODT сначала используется значение из метаданных источника, если оно есть, иначе `Самиздат`; заданный параметр переопределяет источник
- `--rights <string>` - сведения об авторских правах; для ODT сначала используется значение из метаданных источника, если оно есть, иначе `© Шмель, 2026`; заданный параметр переопределяет источник
- `-l, --lang <code>` - язык книги (ISO 639-1)
- `--layout-method {reflowable,pre-paginated}` - режим компоновки EPUB; по умолчанию `reflowable`
- `--css <path>` - подключить CSS-файл к EPUB. Для ODT пользовательские правила добавляются после автоматически созданных стилей; для Pandoc-источников stylesheet передаётся Pandoc. Относительный путь считается от текущей папки.
- `--toc` - добавить видимое интерактивное оглавление в EPUB. Для папки изображений создаются заголовки страниц, на которые ведут ссылки оглавления.
- EPUB-параметры, указанные для другого выходного формата, пропускаются с предупреждением. Если явно заданная папка `--media-dir` для EPUB не существует, программа завершает работу с ошибкой.
- `-m, --media-dir <path>` - папка для автопоиска обложек/медиафайлов (по умолчанию: текущая папка, рекурсивно с подпапками)
- `--split-method {page-break,heading,none}` - метод разбиения EPUB на разделы: `page-break` — по разрывам страниц ODT (по умолчанию), `heading` — по заголовкам, `none` — без разбиения (единая глава)

### Режимы вывода

- `verbose` (по умолчанию) - подробный пошаговый вывод.
- `summary` - по одной строке на файл: `исходный файл — итоговый файл — результат`.
- `quiet` - только критические ошибки; сообщения об успешной обработке и необязательной обложке скрыты.

Примеры:

```bash
python convert.py books/ --mode summary
python convert.py books/ --mode quiet
python convert.py books/ --format epub --input-formats odt,pdf
python convert.py books/ --format pdf --input-formats md --input-formats txt
python convert.py books/ --format epub --input-formats odt,md --output converted/ --no-timestamp
python convert.py books/ --mode quiet --log-file logs/conversion.log
```

### Если выходной файл уже существует

По умолчанию существующий выходной файл пропускается без изменений. Для запроса подтверждения используйте `--ask-overwrite`; для перезаписи без вопроса — `--force`. Если запрос включён, но команда запущена без интерактивного терминала, файл будет пропущен и скрипт сообщит об этом.

```bash
python convert.py document.odt --ask-overwrite
python convert.py books/ --force
```

### Параметры исключений

- `-e, --exclude <pattern>` - дополнительно исключить файл или папку (можно указывать несколько раз, поддерживает glob-паттерны)
- `--exclude-file <path>` - файл со списком исключений (по одному на строку, # для комментариев)
- `--no-recursive` - отключить рекурсивный поиск в поддиректориях (по умолчанию: включен)

Шаблоны проверяются по имени файла/папки, пути относительно обрабатываемой директории и пути от текущей директории. Например, `temp/*` исключает файлы и подпапки внутри `temp`, а `old.odt` — файл с таким именем.

### Автоматическое исключение входных файлов

Входные файлы, имя которых начинается с `_` (например, `_notes.odt`), **автоматически пропускаются** при любом формате результата — и при обходе директорий, и при явном указании файла. Файлы с суффиксом `_Draft` в имени (регистронезависимо, например `test_Draft.odt`) также автоматически пропускаются. Дополнительное исключение через `-e` не требуется.

### Режимы поиска

По умолчанию скрипт рекурсивно обходит все поддиректории. Если нужно обработать только файлы в указанной директории без рекурсии, используйте флаг `--no-recursive`.

### Дата в метаданных

Дата в EPUB файле устанавливается как **дата генерации** (текущая дата и время), а не дата из метаданных ODT документа.

### Язык по умолчанию

Язык книги берётся из параметра `-l`, если он указан; иначе — из метаданных ODT (`dc:language`); при их отсутствии значение по умолчанию — **русский** (`ru`).

### Поддерживаемые форматы изображений

Для обложек и встроенных изображений поддерживаются следующие форматы:

| Формат | Расширения | MIME-тип |
|--------|-----------|----------|
| JPEG | `.jpg`, `.jpeg` | `image/jpeg` |
| PNG | `.png` | `image/png` |
| GIF | `.gif` | `image/gif` |
| WebP | `.webp` | `image/webp` |
| SVG | `.svg` | `image/svg+xml` |
| BMP | `.bmp` | `image/bmp` |
| TIFF | `.tiff`, `.tif` | `image/tiff` |

При автоматическом поиске обложки скрипт ищет файлы с любым из поддерживаемых расширений.

### Значения по умолчанию

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `-c, --cover` | Автопоиск | Ищется файл с тем же именем, что и ODT (.jpg, .jpeg, .png) |
| `-m, --media-dir` | `.` (текущая папка) | Папка автопоиска обложек, рекурсивно с подпапками; отключение рекурсии — `--no-recursive` |
| `-o, --output` | `<имя_odt>_(hh:mm_dd.MM.YYYY).epub` | Наследует имя входного файла с суффиксом даты/времени; `--no-timestamp` отключает суффикс |
| `-t, --title` | Имя файла ODT без расширения | Название берётся из имени входного файла |
| `--identifier` | Автоматический UUID | Сохраняет существующий идентификатор EPUB или создаёт UUID; явное значение задаётся параметром |
| `-a, --author` | Из метаданных ODT | Если не найдено, используется `Шмель` |
| `--publisher` | `Самиздат` | Издатель, записывается в метаданные EPUB |
| `--rights` | `© Шмель, 2026` | Авторские права (`dc:rights`) |
| `-l, --lang` | `ru` | Язык книги (ISO 639-1) |
| `--layout-method` | `reflowable` | Перекомпонуемая вёрстка; доступно также значение `pre-paginated` |
| `--toc` | Выключено | Добавляет страницу интерактивного оглавления в книгу |
| `--split-method` | `page-break` | Метод разбиения на разделы: `page-break`, `heading`, `none` |
| Файлы `*_Draft.odt` | Пропускаются | Черновики не обрабатываются автоматически |

## 🔧 Как это работает

### Процесс конвертации

1. **Чтение ODT** (ZIP-архив)
   - Извлечение `content.xml` - содержимое документа
   - Извлечение `styles.xml` - стили
   - Извлечение `meta.xml` - метаданные
   - Извлечение изображений из папки `Pictures/`

2. **Анализ стилей**
   - Парсинг стилей из `styles.xml`
   - Парсинг автоматических стилей из `content.xml`
   - Определение форматирования: жирный, курсив, цвет, размер и т.д.

3. **Конвертация в XHTML**
   - Обход XML-дерева документа
   - Преобразование элементов ODT в XHTML
   - Генерация CSS из стилей
   - Копирование изображений

4. **Сборка EPUB**
   - Создание структуры EPUB 3.0
   - Добавление метаданных
   - Включение обложки (если есть)
   - Упаковка в ZIP с правильным порядком файлов

5. **Сохранение**
   - Запись EPUB файла на диск

### Структура ODT

ODT - это ZIP-архив со следующей структурой:

```
document.odt (ZIP)
├── mimetype
├── content.xml          ← содержимое документа
├── styles.xml           ← стили
├── meta.xml             ← метаданные
└── Pictures/            ← изображения
    ├── 10000001.jpg
    └── 10000002.png
```

## 📁 Структура EPUB

Сгенерированный EPUB имеет следующую структуру:

```
book.epub (ZIP)
├── mimetype                    ← "application/epub+zip" (без сжатия)
├── META-INF/
│   └── container.xml           ← указатель на content.opf
└── OEBPS/
    ├── content.opf             ← манифест книги (метаданные, список файлов)
    ├── toc.ncx                 ← таблица содержимого (NCX)
    ├── style.css               ← CSS стили документа
    ├── cover.xhtml             ← страница обложки (если есть)
    ├── chapter1.xhtml          ← основное содержимое
    └── images/
        ├── cover.jpg           ← обложка (если есть)
        ├── img_0.jpg           ← изображения из ODT
        └── img_1.png
```

### Описание файлов

- **mimetype** - MIME-тип EPUB, должен быть первым файлом без сжатия
- **META-INF/container.xml** - указывает на основной файл манифеста
- **OEBPS/content.opf** - манифест книги с метаданными и списком всех файлов
- **OEBPS/toc.ncx** - навигационная таблица содержимого (NCX формат)
- **OEBPS/style.css** - CSS стили, сгенерированные из ODT
- **OEBPS/cover.xhtml** - отдельная XHTML страница с обложкой
- **OEBPS/chapter1.xhtml** - основное содержимое книги в формате XHTML

## ⚠️ Ограничения

### Поддерживается

- ✅ Простое форматирование текста
- ✅ Заголовки и абзацы
- ✅ Списки (маркированные и нумерованные)
- ✅ Таблицы с объединением ячеек
- ✅ Встроенные изображения
- ✅ Гиперссылки
- ✅ Цвета и размеры шрифтов
- ✅ Обложка

### Не поддерживается (или частично)

- ❌ Сложные таблицы с вложенными таблицами
- ❌ Плавающие объекты (обтекание текстом)
- ❌ Колонтитулы
- ❌ Сноски и концевые сноски (частично)
- ❌ Формулы (Math)
- ❌ Векторная графика (SVG)
- ❌ Макросы и скрипты
- ❌ Закладки и перекрёстные ссылки

### Известные ограничения

1. **Сложное форматирование** может быть упрощено
2. **Размеры изображений** могут не точно соответствовать оригиналу
3. **Некоторые стили** могут не конвертироваться полностью
4. **Таблицы с сложной структурой** могут отображаться некорректно
5. **PDF с текстовым слоем → EPUB** извлекает текст и не сохраняет исходную вёрстку и изображения
6. Если текстовый слой не найден, **сканированный PDF → EPUB** включает страницы как PNG-изображения; текст в таком EPUB нельзя выделять или искать. Автоматический OCR не выполняется

## 🔍 Решение проблем

### Ошибка: "Файл не найден"

```
❌ Файл не найден: /path/to/document.odt
```

**Решение**: Проверьте путь к файлу. Используйте абсолютный путь или убедитесь, что находитесь в правильной директории.

```bash
# Проверить текущую директорию
pwd

# Список файлов
ls -la

# Использовать абсолютный путь
python convert.py -i /full/path/to/document.odt
```

### Ошибка: "Формат входного файла не поддерживается"

```
❌ Формат входного файла не поддерживается (ожидается ...): document.pdf
```

**Решение**: Проверьте выбранный формат результата. PDF принимается только при конвертации в EPUB (`--format epub`); Markdown и TXT поддерживаются для EPUB/PDF.

### Ошибка: "Файл обложки не найден"

```
❌ Файл обложки не найден: /path/to/cover.jpg
```

**Решение**: Проверьте путь к файлу обложки или удалите параметр `-c` для автоматического поиска.

### Обложка не найдена автоматически

Если обложка не найдена автоматически, убедитесь что:
1. Файл обложки находится в той же папке, что и ODT
2. Имя файла совпадает с ODT (без расширения)
3. Расширение обложки: `.jpg`, `.jpeg`, `.png`, `.gif`, `.webp`, `.svg`, `.bmp`, `.tiff`

```bash
# Пример правильной структуры
document.odt
document.jpg      ← будет найдена
# или
document.png      ← будет найдена
```

### EPUB не открывается в читалке

**Решение**:
1. Проверьте валидность EPUB с помощью [EPUB Validator](https://validator.idpf.org/)
2. Попробуйте открыть в другой читалке
3. Проверьте логи конвертации на наличие ошибок

### Неправильное отображение форматирования

**Решение**:
1. Проверьте, что стили в ODT применены корректно
2. Некоторые сложные стили могут не конвертироваться
3. Попробуйте упростить форматирование в ODT
